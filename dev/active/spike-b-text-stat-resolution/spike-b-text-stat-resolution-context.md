- **Survey of the real text (2026-11-09, throwaway script in the session scratchpad):** escapes are only `

Markup: `<tag>{{text}}` (305 `<enchanted>`, `<crafting*>`, `<nemesismod>`, `<necropolisdownside>`, `<normal>`); the `{{ }}` belong to the markup, no literal braces occur elsewhere. `[Ref|Text]` and `[Text]` (PoE2 about 24,000; PoE1 253, `[DNT]` among them); `[ArmourBreak|Break {0}% of Armour]` holds a placeholder; `<<Icon>>` only in PoE2 (33). - **Decisions:**
  - Markup is stripped before placeholders are parsed: `<tag>{{x}}` -> `x`, `[A|B]` -> `B`, `[A]` -> `A`, `<<I>>` removed; rendered lines are trimmed and empty lines dropped. The extractor's `placeholders` list is checked against our parse (`PlaceholderMismatch` per variant, not a load error).
  - Handler semantics are a table (`NUMERIC_HANDLERS`) with a `Basis`: `PobCited` reproduces `applySpecial` exactly (rounding with PoB `round` = `floor(x*10^d+0.5)`, `%d` truncation where PoB sets no `fmt`, `%g` where it sets `"g"`, `%.2f` for `deciseconds_to_seconds`); `NameDerived` (9 names: `add_one`, `subtract_one`, `divide_by_three`, `divide_by_fifty`, `divide_by_ten_thousand_1dp`, `divide_by_one_hundred_0dp`, `milliseconds_to_seconds_halved`, `multiply_by_one_hundred`, `multiply_by_ten`) follow the same conventions. Neither is game evidence; B2b's `render-check` tests them. `old_leech_percent`, `old_leech_permyriad`, `one_hundred_divide_by_value` stay `Unknown` (no reference, ambiguous name) and the renderer reports them. Placeholder format `-d` is kept as `Other` and reported (`unsupported-format`), not guessed.
  - Known difference from PoB in the renderer: a signed range with fractional values is written with the value format, where PoB writes `%d` (`+(%d-%d)`). Not a divergence-register item yet (Spike C defines the register; B2b's `render-check` will show whether it matters).
  - Variant choice tests conditions on the raw range minimum (PoB `matchLimit`); `gem_quality` and `table_only` variants are skipped unless the caller asks (`VariantFilter`).
  - Include precedence: own file, then includes depth-first in written order (PoB has one parent per file; with at most one include in both installs the order question does not arise yet).
  - Lookup handlers render through a host `Lookup` trait; a missing name, a range, an unknown or malformed handler, an unknown flag, an unknown format, or a variant that renders no text (`empty-line`) is a `NotRenderedReason`, and every input stat that is not rendered (also value 0, no description, declared `no_description`) is returned with its reason.
  - Problems confined to one variant never fail the file load: an unknown variant flag is kept (`unknown_flags`), a handler with a bad argument becomes `Handler::Malformed`, a bad format text keeps its `TemplateError`. File-level shape errors (unknown JSON fields, condition count, hands) still fail the load.
  - Duplicate stats within one file: the first description in file order wins (hypothesis, test `scope_should_use_the_first_description_of_a_stat_within_one_file`); B2b counts affected lines.
  - A range is written as one value only when the numbers are equal (PoB compares `v.min == v.max`), so `%d` can write `(10-10)` like PoB.
  - Lookup tables read from the vendored schema (plan table): six corpus-relevant tables are missing from the extract and go to B1x; key forms (row index, `Index` column, hash) are confirmed in B2b.

## PR B2a: reverse matcher (PR open, in review, branch `spike-b/b2a-reverse-matcher`)
- PR B1x (#15) merged 2026-11-09 as `186b72f` (main CI run 42668239613 green); docs PR #16 merged as `b2fc13f` (main CI run 42669210965 green).
- **`loom-data::stat_desc::invert`:** `shown_text(chain, raw)` writes one raw value as the renderer does (test: equal to `render_description` for every numeric handler); `invert_shown(chain, text)` returns every raw value that shows as `text`, as one `StatValue` interval. Argument: each handler is affine with a fixed sign, PoB rounding and the value formats are non-decreasing, so the shown value is monotone in the raw value; binary search over `i32` (Mods `Stat1Min`..`Stat6Max` are `i32` in the vendored schema, checked 2026-11-09), both ends re-rendered and compared as **text** (so `1.5` for a `%.2f` handler, or `1.5` without a handler, has no interval). Test: for every entry of `NUMERIC_HANDLERS` and about 290 raw values (both signs, rounding steps, domain ends) the interval holds the value and is maximal. `Handler::classify` now uses `numeric_handler` (binary search; the table is sorted, tested). `template.rs` notes that the `Ref` of `[Ref|Text]` is dropped.
- **`loom-parser::resolve`:** `Index::build(&Scope)` keys every variant (both hands of handed descriptions) by its template text with markup removed and each placeholder and literal number replaced by a slot; `Index::resolve(line)` returns `Resolution { line, outcome, shadowed }`.
  - Decisions: line normalization only trims and collapses whitespace (case and punctuation kept: the game's text is exact). Value token = optional sign + number (`d`, `d.d`) or range `(a-b)` with `-` allowed on each end; a sign attaches only if it does not follow a letter, digit, or token. Sign rules: a plain placeholder accepts no sign or `-`; a signed one needs `+` or `-`; a sign written in the template before a plain placeholder must be on the line. A plain range takes no outer sign; a signed range is `+(a-b)` or `-(a-b)` (ends negated). Range value = hull of both ends' raw intervals (`RawValue::Ranged`); one number = `RawValue::Exact` (an interval when a handler rounds). Conditions narrow an exact value; a range only has to meet the condition somewhere (so `(-10-10)% increased` fits the `1|#` variant, as the plan asked). Stats without a placeholder: `RawValue::Hidden { condition, assumed }`, assumed 0 when allowed, else the bound nearest 0 of a one-sided range, else `None` (`!0`); an unsatisfiable condition rejects.
  - Dedupe: per (description, hand) the first verifying variant in file order wins; several descriptions give `Outcome::Ambiguous` (the two hands of a handed description count as two). Filtering is B4a.
  - Include precedence: a description is shadowed when `Scope::find` points another way for one of its stats; shadowed matches go to `Resolution::shadowed`, never to the outcome; only shadowed matches give `Unresolved::OnlyShadowed`. B2b counts lines with a non-empty `shadowed`.
  - Every key match that fails verification is in `Unresolved::NoVariantFits` with a `RejectReason` (`literal-mismatch`, `sign-mismatch`, `value-not-shown`, `inconsistent-values`, `condition-fails`, `unknown-handler`, `malformed-handler`, `unknown-flag`, `unsupported-format`): the evidence B4b needs for `near-miss` and `unsupported-handler`.
  - Left out of the index and counted (`IndexStats`): `gem_quality`, `table_only`, bad templates, templates with no text; **deferred to B2b**: multi-line templates (`deferred_multi_line`) and variants with a lookup handler (`deferred_lookup`).
  - Property tests use a hand-rolled xorshift generator instead of adding `proptest` (no new dependency, deterministic): 3,000 synthetic render-then-resolve round trips over 9 handlers, 3 templates, exact and ranged values; 3,000 over an increased/reduced pair where conditions pick the variant; 20,000 arbitrary lines never panic.
- **`code-architecture-reviewer` (2026-11-09):** no blockers; monotonicity argument confirmed for every handler and chains. Should-fix applied: (1) a later variant of the same description that verifies with **different** values is kept in `Candidate::alternatives` (was silently skipped; test with a positive/negated-negative pair); (2, 3) a placeholder index beyond the hand's stat count or a slot/placeholder count mismatch now counts as `bad_template` (was an uncounted `None`); test asserts every variant is indexed or counted; (4) shadowing compares depth and index only, so a stat in both hands is not shadowed in the off hand (test); (5) handed descriptions give `Ambiguous([Main, Off])` **on purpose** (both hands share the text; picking the hand needs item context, B3/B4a) and B2b reports them separately; (6) a UTF-8 BOM that a PowerShell write added to `stat_desc/mod.rs` removed. Nits applied: `RawValue::Exact` doc on `!v`; empty-chain fast path in `invert_shown` (exact `%d` text, rejects `007`, `-0`, `+5`); renderer-equality test for handler chains; read-back property no longer skips silently, plus a second property over the increased/reduced pair (3,000 cases, variant chosen by conditions). Kept: a template that is only a placeholder (`{0}`) gets key `#` and matches any bare number line (real, B2b counts them); `loom-parser`'s unused `loom-domain` dependency (pre-existing).
- **Known limits (for B2b to measure on real data):** a template whose placeholder touches digits (`{0}{1}`, `{0}5`) or sits in literal parentheses with a dash (`({0}-{1})`) tokenizes differently from its rendered line and will not match; thousands separators are not read; a `Not(v)` condition inside an exact interval only moves an end.
