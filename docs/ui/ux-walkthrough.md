# UX walkthrough of the real app (2026-11-14)

The UX side project's walkthrough (handoff, Next action; brief `dev/active/ux-improvements/ux-improvements-notes.md`). Every screen of the real app, end to end, with each friction point, a screenshot, and a suggested fix. **The maintainer picks the fixes** from the pick list at the end. The maintainer put all UI work in this sprint (2026-11-14) and asked for the High items first: UX-01 to UX-04 are fixed (see "Fixed" below), and most Medium and Low items since ("Fixed after the High items"); the pick list shows what is open.

## How it was run
- App: `dev` at `1325bb8`, `cargo build --locked -p loom-tauri --features e2e,tauri/custom-protocol` with `pnpm build` in `ui/`, on Windows 11 (WebView2 157), driven over WebDriver (`tauri-driver` 2.1.0, `msedgedriver` 157.0.4341.46) with a 1440 x 900 window (one check at 1024 x 700). The `e2e` feature replaces the native file dialogs with fixed files, so the folder picker for game data and the real save and open dialogs were not exercised (their titles and suggested names are read from `crates/loom-tauri/src/lib.rs`).
- Data: `local/p3/p3-8n/bundle-poe1-a` (PoE1, data schema 3; `bundle-check` no findings); first start without `LOOM_BUNDLE_DIR` and with an empty data folder.
- Builds: `smite-inquisitor-act10.xml` as a share code (made with zlib and URL-safe base64, as PoB does), `ice-nova-elementalist-mapping.xml` as a file, `ice-nova-elementalist-campaign.xml` pasted as XML (all `tools/oracle/fixtures/community/`). The Smite build has 7 item sets and 119 items, which brings out most of the list problems.
- Not covered: a screen-reader pass, zoom, and the native dialogs (above). Screenshots are in `docs/ui/ux-walkthrough/` (scaled to 1440 wide; the folder path in 18 and 23 masked).

## What works
Import by share code, pasted XML, and file; the item edit preview with before and after values; apply, undo, and redo give the right values; save, close, reopen keeps the edit; recovery after a hard kill offers the work back and restores it; XML and share code export (with "Copied" feedback); the AI connection screen with safe defaults; at 1024 wide the layout stacks into one column without a horizontal scroll.

## Findings
Severity: **High** loses work or misleads; **Medium** gets in the way of a common task; **Low** polish. Size: **S** under a day, **M** a few days, **L** a PR of its own or more.

## Fixed (2026-11-14, the High items)
- **UX-01**: Close build with unsaved changes asks first (Save and close, Close without saving, Cancel); a cancelled or failed save keeps the build open. A clean build closes at once. ui/src/App.tsx (CloseDialog), ui/src/store (closeBuild).
- **UX-02**: Equipment lists the items in use first, in inventory order (jewels in allocated sockets as "Passive tree"); the others are folded under "N items not in use" with the item sets that hold them. An item set picker switches the active set as one undoable step (new command use-item-set, history kind item-set, error APP_ITEM_SET). The item editor says when an item is not in use (UX-06's editor half).
- **UX-03**: what is "in use" comes from the engine (loom_calc::poe1::collect::items_in_use, kept in step with the calculation's own item collection): app API v1 gains BuildView.in-use-completeness, ItemSummary.in-use, sets, `tree-socket`, and WarningView.in-use (all additive). The header, the side menu count, the dashboard, the import review, and the Warnings screen (split into "On items in use" and "On items not in use") count only warnings the calculation reads. The Smite build now opens as "Exact"; switching to "Red Maps" gives "Partial · 4 warnings".
- **UX-04**: the breakdown is an outline of steps in words (`term.*`, `kind.*`, `constant.*` messages, other IDs read as their words; A × B ÷ 100 reads as A × B%; a field's node is named by its field). Selecting a step lists its sources, grouped by what they change, with the effect as the game says it ("+79% increased", "36% more"); identical rows show once with "counted in N steps". Sources are named: slot and item with the line's text, passive node names (BuildView.passive-names), gem names (BuildView.skill-groups), configuration inputs and rules in words. The full node tree stays behind "Show every node".
## Added after the High fixes (2026-11-14, maintainer's notes)
The maintainer asked for a skills page like other planners' (socket groups as cards), a **global stage choice** (PoB's loadouts: "Level 1-12", "Early maps", "Endgame") that sets the gear, the gems, and the passive tree together, and stated the aim: a build planner shows almost every part of the build and lets the user change it.
- **Stage picker** in the header (`loom_app::loadout`): each passive spec is a stage; item, skill, and config sets link to it by PoB's `{n}` title links, else by title, else the kind's only set. Choosing one switches all four as one undoable step (command `use-loadout`, error `APP_LOADOUT`). A build saved with mixed sets shows "Act 10 (sets mixed)". Titles show without PoB's colour codes and links.
- **Skills page**: the active skill set's socket groups as cards; each gem with a colour mark (round for an active skill, square for a support; a token colour, no game art, ADR-000), level, quality, and on or off; the group on or off; the main skill chosen per gem ("Make main"); a skill set picker. Commands `use-skill-set`, `edit-gem`, `edit-socket-group` (error `APP_SKILL`), each one undoable step that reaches the PoB export.
- **UX-11 fixed**: the main skill is the active skill the main group's `mainActiveSkill` names (Smite, not "Leap Slam, Faster Attacks, Smite, Momentum").
- **Open question (Q-UX-1)**: the build keeps one main socket group number (`mainSocketGroup`) for every skill set, so after a stage switch it can point at another group (Smite's "Red Maps" shows Flesh and Stone). What PoB does on a skill set switch needs a check in PoB's source before Exiled Studio picks a rule. **Answered by the maintainer 2026-11-15:** PoB handles the main skill poorly; Exiled Studio picks its own default instead of following PoB's number. An active skill gem is usually the main skill: supports, auras, and other gems that deal no damage weigh less. Among the rest, the skill with the highest damage is the default. Some builds deal damage with two or three skills together (Righteous Fire's burning, with Fire Trap igniting the enemy), so the damage shown should look for such pairs and combine them. Needs the calculation to compute those skills first: today only Ice Nova and Smite hits are computed (Phase 3 slice), so the rule can rank only the skills the engine computes and falls back to the active-gem weighting otherwise.
- **Sockets and links** (maintainer's note with a pobb.in example, 2026-11-14): the Skills page is now one card per equipment slot, with the item's name and its sockets drawn as coloured circles joined by link bars (filled where a gem sits). Under the slot are its socket groups, with each active skill at the top and the supports that support it indented beneath. A support goes under the main skill when it supports that, else under the first active it supports, and notes "also supports …" for the others. Supports that support nothing in the group are listed apart and muted. A group whose gems span link groups is marked "Not all linked", and gems past the item's sockets are marked "without a socket". Groups without a slot go in "Other skills". The Equipment list draws the same sockets. Sources:
  - The links come from the game data's support rules (`loom_calc::poe1::skill::group_links`, PoB's `supports` with the types enabled supports add).
  - The sockets come from the item's `Sockets` line.
  - A slot's groups fill its sockets in order, as PoB does.
  - App API v1 gains, all additive: `GemView.supports`, `GemView.socket`, `ItemSummary.sockets`.
  - The maximum socket count by item type (6 body and two-hand, 4 helmet, gloves, boots, 3 one-hand) is not checked yet; it belongs with item editing (B-2).
  Screenshot: [`31-skills-sockets.png`](ux-walkthrough/31-skills-sockets.png).
- **Add and remove gems and socket groups**: each group has "Add gem", which opens a gem picker over the game data, and a remove button on each gem. "Group settings" holds the group's label, its slot, and "Remove group", and each slot card has "Add a socket group in {slot}". Each change is one undoable step that reaches the PoB export. Details:
  - The commands are `add-gem`, `remove-gem`, `add-socket-group`, and `remove-socket-group`. `edit-socket-group` gains `slot` and `label`, where an empty string clears either. All are additive to app API v1.
  - Opaque content in a group stays where it was (`Ordered::insert_typed`, `remove_typed`).
  - A new gem takes level 20, or the gem's highest level when that is lower, and quality 0.
  - The picker (`loom_app::gems::catalog`, Tauri command `gems`) has Skills and Supports tabs and a search by name or exact tag.
  - Supports that support a skill in the group come first (`loom_calc::poe1::skill::fits_group`, the same rule as the links). The others are folded under "Supports that support nothing in this group".
  - The picker stays open, so a whole link can be filled in one go.
  Screenshot: [`32-gem-picker.png`](ux-walkthrough/32-gem-picker.png).
- **Gem names**: most of the data's gem effects leave their name to the gem item, so the name falls back to the base item's. The picker leaves out these:
  - Unreleased placeholders (`[DNT]`).
  - Path of Exile Royale gems. PoB's `bases.lua` skips base items whose ID contains `Royale`, as the extractor's cross-check records.
  - A Vaal gem's leftover `AltX` and `AltY` effects, which repeat the gem's own name.

  Two gems with the same name (Convocation and ConvocationOld) both stay, each shown with its data ID.
- **Configuration page** (2026-11-14, the agent's pick after the maintainer left the order to it): a "Configuration" page in the side menu shows the active config set and makes it editable.
  - **Inputs:** grouped as Enemy, Charges, Conditions, and Other, and named in words ("conditionFullLife" reads "Full life", PoB's key beneath). Each has an editor by type: a check box, a number, or text.
  - **What each input does:** it comes from the engine's own rule (`loom_calc::poe1::collect::input_use`, the per-input rule the collector already used, now shared). No mark means the calculation applies it. "Changes no number" means it only sets names no mapped modifier reads, or is a default the enemy model derives. "Not calculated yet" means it is a reason, so the numbers are partial.
  - **Defaults:** default values that change no number are folded away, 20 of the Smite build's 49 inputs.
  - **Editing:** any input can be removed, and one can be added by its PoB name.
  - **Custom modifier blocks:** each has an on or off switch and its text. "Apply text" reads the lines again by PoB's rule (`pob_xml::custom_modifier_lines`) and resolves them as an import does. Each line shows "Not calculated" when it matched nothing, or "Note, no effect" (ADR-015 Amendment 2). Blocks can be added and removed.
  - **Config set picker**, when the build has more than one.
  - **Undo and export:** every change is one undoable step ("configuration change") and reaches the PoB export.

  App API v1 gains these, all additive: `BuildView.config` (inputs with `effect`, blocks with their lines' status), the commands `use-config-set`, `set-config-input`, `remove-config-input`, `edit-custom-block`, `add-custom-block`, and `remove-custom-block`, history kind `config`, and error `APP_CONFIG`. PoB's legacy `customMods` input is shown, not set. Checked in the real app: turning off frenzy charges takes the Smite build's hit DPS from 91,415 to 78,622, and undo restores it.

  Not yet: the full list of PoB's options with their own labels and choices. Today the page lists only the inputs the build has, plus adding one by name. Screenshot: [`33-configuration.png`](ux-walkthrough/33-configuration.png).
- **Still to do for "see and change everything"**: the passive tree (the planned Phase 5 editor, PR #107's plan), the item slots (B-2), and a catalogue of PoB's config options (labels, choices, defaults) so any option can be picked from a list.

## Fixed after the High items (2026-11-14)
- **UX-07**: each modifier line shows as the game prints it, with no markup and its roll applied, and the raw PoB line appears only after "Edit". Crown of Eyes' `{variant:2}{range:1}+(300-350) to Accuracy Rating` reads "+350 to Accuracy Rating".
  - The rule is `pob_item::shown_text`, display only. Each `(a-b)` of a line with `{range:r}` becomes PoB's `applyRange` value, `a + r x (b - a)`, rounded away from zero at the ends' decimals. Lines with no `{range:}`, or with a value before the range, show as written.
  - The line's variants ("Variant: Current") and marks ("Crafted", "Fractured") are badges.
  - App API v1 `LineView` gains `shown`, `variants`, and `marks`, all additive.
- **UX-08**: an item card under the name shows sockets, quality, item level, required level, base values ("Energy Shield: 276"), influences, and flags ("Corrupted"). PoB's file fields ("Prefix: None", "Implicits: 0", "Selected Variant: 2") are folded under "File fields (n)", kept as written. App API v1 gains `ItemView.card`, additive.
- **UX-09**: a variant picker on the card. It is one undoable item edit: the new `LineOp::SelectVariant` writes the item's `Selected Variant` line, or adds one after the variants when it is missing, and the item is read and resolved again, so the other variant's lines become "Not used". It is locked while line changes are open. Checked in the real app: Crown of Eyes from Current to Pre 3.7.0. Screenshot: [`34-item-card.png`](ux-walkthrough/34-item-card.png).
- **League setting** (maintainer 2026-11-14, after asking for a game-version choice: a strict version rule would break Standard's legacy items and choice variants, so a league setting instead). Each build has a league, Challenge league (the default) or Standard, picked on the Equipment and Configuration pages as one undoable change and saved in the build document (build v1 `league`, additive, accepted 2026-11-14; PoB's format has no place for it, so a PoB export leaves it out). Variants are told apart by PoB's naming (`pob_item::variant_eras`): legacy versions (`Pre 3.7.0`, `Fire (Pre 3.14)`, and a bare `3.19.0` when another variant says `Current`), current versions (`Current`, `Frenzy Current`, or a bare version alone), and choices (`Fire`, `Life`). The picker is labelled "Item version" when the variants are versions and "Kind" when they are choices; legacy options say "(legacy)". In a challenge league an item on a legacy version gets a "Legacy" badge in the equipment list and a note on its card with "Use current version", which picks the matching current variant (`pob_item::current_variant`); in Standard the note only says Standard keeps it. Modifier tiers (tier 1 the best roll) are a separate thing, left for B-2. Checked in the real app: Crown of Eyes to Pre 3.7.0, the note, "Use current version", undo, Standard. Screenshot: [`35-legacy-version.png`](ux-walkthrough/35-legacy-version.png).
- **B-2, first part: the equipment panel** (maintainer 2026-11-14: lay it out as the game's inventory and show the game's hover tooltip, from the maintainer's in-game screenshots). The Equipment page opens with the active item set laid out as the game's inventory: weapons tall at the sides with the I / II weapon swap above each, helmet, body armour and belt down the middle, amulet and rings beside them, gloves and boots below the weapons, five flasks along the bottom, and the game's square left of the flasks (drawn, nothing tied to it yet). A step that does not read cuts the history there (newer steps stay; undo never skips a state). Redo is not kept.
