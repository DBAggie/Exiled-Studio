## Bundled PRs
**Bundle related work into one PR where possible** (maintainer 2026-11-25, ADR-012 Amendment 1: CI takes a very long time). Tasks of one list or steps of one plan go on one branch, a commit per step; continue the open PR when it fits, and open a new one only for unrelated work or when the open one is merged or under review. Push per finished step, not per small change. Before opening the PR, and on every later push, update every document it made stale (the handoff's Current state and Next action; the full list is in `AGENTS.md`, "Bundled PRs"). Run `/dev-docs-update` for planned tasks. **Right after `gh pr create`, before any other work, push a follow-up commit that writes the PR number into the handoff's Current state and every other doc that names the PR** (`AGENTS.md`, "When to update"). The next session must be able to resume from the repository alone.

## Hard rules
- Never modify the legacy repository at `D:\POE Dev\PathOfBuilding`. Read only.
- Game files are read only to derive data for accuracy. Never copy GGG art, audio, or other assets into this project (ADR-000). The one exception: GGG's published passive tree export sprite sheets, fetched at a pinned commit by `tools/tree/` and shipped only inside signed data bundles, never committed (ADR-005 Amendment 2).
- The game is the truth; PoB is the pinned regression oracle. Every difference from PoB needs evidence and a divergence-register entry (ADR-001/006).
- Modifiers are stat-ID first; never silently drop content you can't resolve (ADR-015).
- Core crates must stay wasm32-compatible: no fs, threads, clocks, or network (ADR-016).
- No telemetry. Network access only in integration adapters (ADR-011).
- PRs are one coherent body of work, bundled where possible, and carry their own evidence for every step: tests, parity/divergence diff, and coverage touched (ADR-012 with Amendment 1).
- `main` and `experimental` are protected. Work on a branch from `dev`, open the PR against `dev`; commit or push only when the maintainer asks. Merging into `experimental` or `main` is the maintainer's.

## Workflow
- Persistent task docs: `/dev-docs <task>` creates `dev/active/<task>/`; `/dev-docs-update` refreshes them before a context reset.

- Rust code follows the `rust-best-practices` skill. Lint: `cargo clippy --all-targets --all-features --locked -- -D warnings`. Use `#[expect(...)]` with a reason instead of `#[allow(...)]`.
